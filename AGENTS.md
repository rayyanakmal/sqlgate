# AGENTS.md

## What this project is

SQLGate — natural language to safe, executable SQL through a deterministic gate.
The demo-able version of the Hitachi internship pattern: a proposer (stub / DeepSeek /
fine-tuned) proposes intent + slots; deterministic code renders, validates, and executes.
Output is either an exact, executed-verified SQL query or a structured rejection with a reason.
Nothing from Hitachi: toy e-commerce SQLite schema, Spider-subset corpus, zero fabricated demo data.

## Stack & Conventions

**Standard:** `code-style-conventions` R1–R6 — ruff format enforced; descriptive names, no
lookalike identifiers; type hints on all functions; comments say WHY not WHAT; happy path first;
no dead code or speculative abstraction.

**Python (library + typer CLI + Streamlit UI):**
- `ruff format` + `ruff check` + `mypy` before commit
- CLI: typer commands under `sqlgate.cli:app`
- Eval artifacts are data, not code — commit generated eval sets, never generated reports
- Schema + pattern library live in `data/` (authored, human-reviewed)
- `sample.db` is generated by `scripts/build_db.py` (seeded, regenerable) — never hand-edited

## Core invariants (do not weaken)

1. **Deterministic wins on conflict.** The gate decides. The proposer only proposes.
2. **Reject-with-reason is the default posture.** No silent fixes, no guessing.
3. **False-accepts = 0 is the headline metric.** Safety first, throughput second. A regression
   here is a release blocker.
4. **Cross-intent override is blocked.** A proposer proposal contradicting the stub's owner-intent
   classification is rejected.
5. **Correctness is proven by execution against the read-only DB**, never by string comparison
   in app code.
6. **Zero fabricated demo data.** Every sample question traces to a provenance record
   (Spider source or tagged authored golden data).

## Build Rules

- Spec-first: SPEC.md is the contract. Code follows it. Change the spec first, then rebuild.
- TDD: every Given/When/Then in SPEC.md maps to a test. RED → GREEN → REFACTOR.
- Verify against ACs after every story: `uv run pytest -x --tb=short`.
- Ponytail ladder before any code: need it? stdlib? native? existing dep? one line? then minimal.
- The execution oracle uses the REAL sqlite3 engine with `mode=ro` — never a mock.
- The gate never changes when a proposer changes (AC-1.5).

## Pipeline Context

```
question → [proposer: intent + slots] → [gate: intent_validate → schema_validate →
safety_rules → sql_render → parser_check → execution_oracle] → exact SQL  OR  rejection
```

Modes: offline stub (no key, always runs), DeepSeek LLM (capped in public demo), fine-tuned
LoRA (local Mac, committed comparison table). Eval layers (corpus/golden/adversarial/mutation)
are committed scripts with seeded regeneration.
